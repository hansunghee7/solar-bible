# 구PC 헤르메스 셋업 1단계: 설치와 소통 레인용 프로필 하나 (로컬 탐 -> 타미)

받는이: 타미
보낸이: 로컬 탐 (2026-10-08, 사장님 지시 원문: "헤르메스 타미를 활용해 구피시에 헤르메스를 셋업해라. 탐과 로컬탐이 활용방안을 생각해서 셋업하고, 핏은 영상생성 워커를 구피시에서 관리하는 전용 헤르메스를 셋업하고 싶다. 비티나 덱스가 컨펌하게 해도 좋다")
성격: 구PC에 헤르메스 CLI를 새로 설치하고, 신PC 타미 줄과 섞이지 않는 별도 프로필 1개를 만든다. 클로드 크레딧은 쓰지 않는다(스크립트, 타미, 무료 풀만).

## 점검으로 확인된 현재 상태 (로컬 탐, ssh 읽기 전용, 2026-10-08)
- 구PC(goosolar)는 Linux 7.0, RAM 15GB 중 약 3GB 여유, 디스크 77GB 여유, GPU 없음(nvidia-smi 없음). 무거운 로컬 모델은 올리지 않는다.
- `hermes` 명령은 없다. 기존에 `~/hermes-agent/telegram_agent.py`(자체 파이썬 봇)가 상시 실행 중이니 건드리지 않는다.
- 신PC 헤르메스는 v0.21.3(포크 +1081 커밋)이며 설치 경로는 `C:\Users\PC\AppData\Local\hermes\hermes-agent`다. 구PC에는 같은 포크가 아니라 설치 가능한 공식 방식 또는 신PC 사본을 쓴다. 어느 쪽인지는 타미가 근거와 함께 고른다.
- 감시와 정리 크론(`pending_watchdog`, `pending_reaper`)은 이미 구PC에서 도는 중이다. 건드리지 않는다.

## 설계 원칙
- 레인 분리: 프로필(HERMES_HOME)을 `~/.hermes-ops`로 따로 둔다. 신PC 타미 대기열과 섞이지 않게 `tasks/pending/` 감시는 이 프로필에 연결하지 않는다(1단계에서는 수동 호출만).
- 권한 최소: 1단계 프로필은 읽기와 solar-bible 안의 지정 폴더 쓰기만. 계정 생성, 결제, 외부 발송, 키 값 입력은 하지 않는다.
- 핏 전용 영상 워커 헤르메스는 2단계다. 영상 워커 명세(어떤 폴더, 어떤 스크립트, 한도 규칙)는 핏이 정한 뒤 별도 의뢰한다. 1단계에서 만들지 않는다.

## 순서와 성공 증거 (모든 검증은 스크립트로, 눈으로 확인 금지)
1. 설치 방식 선택: 신PC 설치 기록과 공식 문서를 근거로 한 줄 결론을 쓴다. 구PC 기존 파이썬 환경(`~/hermes-agent/venv`)은 건드리지 않고 새 가상환경을 쓴다.
2. 설치 후: `HERMES_HOME=~/.hermes-ops hermes --version` 출력 원본.
3. 프로필 점검: `HERMES_HOME=~/.hermes-ops hermes chat --oneshot --query "구PC 헤르메스 점검: 오늘 날짜와 사용자 홈 폴더 이름만 한 줄로 답해"` 가 종료 코드 0이고 홈 폴더 이름(goosloar)이 답에 있는지 `grep -q goosloar` 로 판정.
4. 모델 경로: 무료 풀(옴니라우터 콤보)을 쓴다. 키가 필요하면 값은 어디에도 출력하지 않고 카빗 패스 참조로만 연결한다. 못 하면 `[사람 개입 필요: 자격증명]` 한 줄만 올리고 멈춘다.
5. 메모리·디스크 영향: 설치 전후 `free -m` 과 `df -h ~` 한 줄씩을 붙인다. 가용 메모리가 1.5GB 아래로 떨어지면 되돌리고 보고한다.

## 하지 말 것
- 크론 등록, 서비스 상주 등록(systemd), 기존 `telegram_agent.py` 수정은 이 단계에서 하지 않는다. 필요해 보이면 제안만 적는다.
- 삭제는 이 의뢰로 만든 `~/.hermes-ops` 와 새 가상환경에 한한다. 그 밖의 삭제 금지.
- 쓰기가 거부되면 우회하지 말고 거부 문구 원본을 보고한다.

## 보고

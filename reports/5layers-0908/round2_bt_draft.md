## 지시서 1: 세션 시작 훅 동기화 로직 수정
- **목적**: `.claude/hooks/session-start.sh`에서 변경 사항이 있어도 강제 동기화(`ff-only`)가 수행되도록 수정하고 검증함.
- **실행 명령**:
  1. `52행`의 조건문을 제거하여 `git pull --ff-only`를 무조건 실행하게 변경함.
  2. 세 가지 환경 시험: (A) 깨끗한 상태, (B) 로컬 비충돌 변경, (C) 원격과 충돌하는 변경.
  3. `git hash-object`로 C 케이스 전후의 파일 해시를 대조함.
- **성공 기준**: 
  - (A, B) 성공 시 종료 코드 0. 
  - (C) 실패 시 `git pull`의 오류 메시지 출력 확인 및 해당 파일의 해시가 이전과 동일함(스크립트 비교 결과: 일치).
- **하지 말 것**: `git reset --hard`나 `stash` 명령 사용 금지.
- **보고 형식**: 테스트 실행 완료 후 마지막 5줄 결과.
- **막히면**: 우회하지 말고 `git pull` 거부 문구 원문 그대로 보고.

## 지시서 2: 문서 색인 갱신 타임아웃 진단
- **목적**: `scripts/ops/docs_incremental.py`의 90초 초과 실패 원인 규명 및 수정 후보 작성.
- **실행 명령**:
  1. `scripts/ops/jobs.toml`에서 `fn:opsdb-docs` 항목의 `timeout` 설정 존재 여부 확인(grep).
  2. `time python scripts/ops/docs_incremental.py`를 실행하여 현재 수행 시간 측정.
  3. 측정 시간이 90초 초과 시 `timeout = 900`을 추가한 diff 파일 작성.
- **성공 기준**: 측정된 소요 시간을 숫자로 출력하고, diff 파일의 `timeout` 키 존재 여부를 스크립트로 검증.
- **하지 말 것**: 실제 코드에 즉시 적용(수정 파일은 `apply_candidate.diff`로 저장).
- **보고 형식**: 실행 후 마지막 5줄(시간 측정치 포함).
- **막히면**: 스크립트 실행 불가 시 종료 코드 보고.

## 지시서 3: 기록 인용 규칙 강화
- **목적**: `.claude/hooks/check-tone.py`에 인용 규칙(출처 및 시각 필수) 정규식 추가.
- **실행 명령**:
  1. `check-tone.py` 내에 "기록을 인용했다고 스스로 밝힌 문장"이 출처와 시각을 포함하는지 확인하는 정규식 로직 추가.
  2. 3개 테스트 문장 검증: (1) 출처와 시각 있음(통과), (2) 인용 밝혔으나 출처 없음(경고), (3) 기존 [추정] 표기(통과).
- **성공 기준**: 스크립트가 각 입력에 대해 `[통과, 경고, 통과]`를 반환하는지 대조 확인.
- **하지 말 것**: 기록을 인용하지 않은 문장에 대한 강제 규칙 적용 금지.
- **보고 형식**: 검증 스크립트 실행 마지막 5줄 결과.
- **막히면**: 정규식 파싱 오류 시 원문 보고.

## 지시서 4: 미커밋 변경 비공개 로컬 스냅샷
- **목적**: 미커밋 변경 파일을 분류하고 `C:/work/_ops/dirty_snapshots/<날짜>/`로 복사.
- **실행 명령**:
  1. `git ls-files --others --exclude-standard`로 미커밋 목록 추출.
  2. 규칙에 따라 분류: [런타임·산출물], [공개 가능 문서], [모름].
  3. [모름] 폴더 내부 파일은 로컬 LLM으로 한 줄 설명을 생성하여 `dirty_report.json`에 저장.
  4. 모든 파일(원본 보존)을 지정된 경로로 복사.
- **성공 기준**: 대상 경로에 파일이 생성되었는지 `ls -R`로 확인하고, `dirty_report.json` 내 "모름" 항목의 설명 존재 확인.
- **하지 말 것**: 원본 파일 삭제 또는 외부 LLM API 호출.
- **보고 형식**: `dirty_report.json` 마지막 5줄.
- **막히면**: 경로 접근 권한 오류 시 원문 보고.

## 지시서 5: 기록 불일치 점검 (정적 분석)
- **목적**: `docs/` 내 문서와 운영 DB(공정 카드) 간 항목 대조.
- **실행 명령**:
  1. `git ls-files docs`로 문서 목록 수집.
  2. `scripts/ops/opsdb.py`를 사용하여 공정 카드 목록을 JSON으로 추출.
  3. 양쪽을 대조하여 목록화 (`discrepancy.json` 생성).
- **성공 기준**: 출력 목록의 각 항목이 실제 원본 파일/DB에 존재함을 스크립트(exists 확인)로 검증하고 결과 리포트 출력.
- **하지 말 것**: GCP Vertex 판정 결과에 의존하여 "맞다/틀리다" 결론 내리기.
- **보고 형식**: `discrepancy.json` 마지막 5줄.
- **막히면**: 종료 코드 2 또는 3 보고.

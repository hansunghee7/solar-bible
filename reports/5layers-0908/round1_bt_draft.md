## 지시서 1: 세션 시작 훅 강제 동기화 구현
- 목적: 미커밋 변경 사항이 있어도 `git pull --ff-only`가 실행되도록 로직 변경 및 3개 시나리오 검증.
- 실행 명령: 
  1. `.claude/hooks/session-start.sh` 52행 조건을 `[ -n "$(git status --porcelain)" ]`에서 무조건 수행하도록 수정.
  2. 임시 저장소에서 다음 3개 상태(A: 깨끗함, B: 겹치지 않는 변경, C: 겹치는 변경)를 재현하고 `session-start.sh`를 실행.
  3. 성공 시 `git status` 결과를 `verify_sync.log`에 저장.
- 성공 기준: `verify_sync.log`에서 세 경우 모두 exit code 0 확인 및 변경 사항 유지 확인(grep -v 활용).
- 하지 말 것: `git reset --hard` 사용 금지, main 직접 push 금지.
- 보고 형식: `git status` 최종 결과물 마지막 5줄.
- 막히면: 실행 중단 후 "git pull 거부 메시지" 원문 전체를 보고.

## 지시서 2: 문서 색인 갱신 Timeout 원인 분석
- 목적: `docs_incremental.py`의 `TimeoutExpired` 원인을 로그 기반으로 진단하고 수정안 2개 도출.
- 실행 명령:
  1. `logs/incremental.log`에서 10/7 16:38 이후 모든 에러 로그 추출.
  2. `os.walk`로 대상 파일 개수와 `time` 명령어로 총 소요 시간 측정.
  3. 결과 분석하여 [수정안 1: 배치 크기 감소], [수정안 2: 타임아웃 제한 시간 증대] 후보 파일 작성.
- 성공 기준: 진단 파일 `diagnosis.txt` 내 원인 키워드(메모리 부족 또는 IO 대기) 기록 확인.
- 하지 말 것: 로그 임의 수정, BGE-M3 모델 직접 호출.
- 보고 형식: `diagnosis.txt` 마지막 5줄.
- 막히면: 실패한 작업의 stderr 원문 그대로 보고.

## 지시서 3: 기록 인용 출처·시각 표기 규칙 확장
- 목적: `.claude/hooks/check-tone.sh`에 인용 시 출처 및 시각 표기 강제 규칙 추가.
- 실행 명령:
  1. `check-tone.sh` 내 정규식 패턴에 `(출처:.*, 시각:.*)` 누락 시 경고하는 로직 추가.
  2. 기존 "추정" 표시 규칙과 통합.
  3. 테스트 텍스트 3개를 넣어 경고 발생 여부 확인.
- 성공 기준: `grep` 명령으로 새 규칙 패턴이 파일 내 존재함이 확인되고 테스트 파일에서 경고 발생.
- 하지 말 것: LLM 판정 로직 호출, 문맥 분석 금지(패턴 매칭만 수행).
- 보고 형식: 수정된 `check-tone.sh` 마지막 5줄.
- 막히면: 스크립트 문법 오류 메시지 원문 보고.

## 지시서 4: 미커밋 변경 파일 자동 분류기 생성
- 목적: 로컬 미커밋 변경 파일을 런타임/문서/모름으로 분류하고 목록화.
- 실행 명령:
  1. `git status --porcelain` 결과를 읽어 경로 규칙(런타임: `h_send/`, `reports/`, 문서: `docs/`, 기타: 모름)에 따라 분류.
  2. "모름" 분류 항목만 헤르메스 엔진에 전달하여 한 줄 설명(판정 금지, 설명만) 추출.
  3. 결과를 `tstate.json` 형태의 파일로 저장.
- 성공 기준: 스크립트 실행 후 `tstate.json` 파일 생성 및 내부에 카테고리별 키 존재 확인.
- 하지 말 것: 결과물 자동 commit, 로컬 파일 임의 삭제.
- 보고 형식: `tstate.json` 마지막 5줄.
- 막히면: 분류 불가 파일 경로와 이유를 그대로 보고.

## 지시서 5: GCP Vertex를 활용한 문서-공정 불일치 대조
- 목적: `docs/` 내 문서와 공정 카드의 항목 간 불일치 및 누락 항목 식별.
- 실행 명령:
  1. `scripts/ops/ask_vertex.py`를 실행하여 문서 파일명과 공정 카드 리스트 간의 누락 항목 비교.
  2. 결과는 [문서명, 공정카드 항목, 차이점(위치 정보 포함)] 리스트로 출력.
  3. 판정(옳고 그름)은 제외하고 오직 존재하지 않거나 불일치하는 지점만 리스트업.
- 성공 기준: 출력된 리스트가 0개 이상이며, 파일 내용과 대조 시 일치 여부 확인 스크립트 통과.
- 하지 말 것: 결과에 대한 "권장 조치" 작성 금지, 판정 금지.
- 보고 형식: 분석 리포트 `diff_report.txt` 마지막 5줄.
- 막히면: Vertex API 응답 헤더 및 에러 메시지 원문 보고.

# 스크립트 활용 방식 (정본, 사장님 10/9 "지금 스크립트 활용 방식도 정본의 하나로 저장")
공정 카드 탐 #36과 같은 내용. 예시 스크립트는 이 폴더와 저장소 scripts/ops/, tasks/assets/ 에 있다.
1. 사람과 LLM에게는 "명령 한 줄 + 성공 기준 한 줄"만 준다. 단계 기록(STATE)과 검증은 스크립트가 한다(예: exp1_run.sh, tami_exp_check.sh).
2. 머리가 필요한 단계만 스크립트가 API를 부른다(api_run.py). 관문은 코드로: 하루 상한, 키 없음, 종료 코드 0/2/3/4, 장부 기록. 값은 출력하지 않고 이름·길이만.
3. LLM이 낸 인용은 스크립트가 원문에 글자 그대로 있는지 센다(환각 제거). 판정은 사람이나 탐이 한다.
4. 스크립트 하나의 합격 조건: 문법 확인(bash -n, py_compile), 격리 복사본이나 가짜 서버로 자체 시험, 실제 데이터로 1회, 증거 로그. 그다음에만 저장소 반영(PR, build pass일 때만 병합: merge_when_green.sh).
5. 기다림은 폴링 스크립트를 run_in_background로 걸고 끝나면 텔레그램으로 알린다(e1b_watch.sh, pass_watch.sh). 주기 작업은 1회 실행 증거 → 감시 대장 등록 → 첫 자동 실행 확인.
6. 읽기 전용 점검과 쓰기를 나눈다. 쓰기(설치, 삭제, 등록, 키 이동)는 되돌릴 방법을 먼저 적고, 시험 통과 뒤에만 한다(sa_key_to_vault.sh의 순서 오류 교훈: 시험 후 보관).
7. 위임 순서는 스크립트·ssh 직접 → 로컬 LLM·무료 풀 → 타미·덱스 → Vertex → 클라우드 → 소넷 서브에이전트 → 본 세션(핏#52). 막히면 추측 재시도 대신 로그 원문을 보고하고 우회하지 않는다.
8. 한글과 윈도우: PYTHONUTF8=1, 파일은 UTF-8, 덱스 출력의 한글은 \uXXXX로, 경로는 C:/ 형식, 서비스(예: Parsec)가 프로세스를 되살리는 것을 확인한다.
미검증 항목: night_*.py는 이번 세션의 1회 실행 증거만 있다(야간 일감 1: 인용 검증 5/5, N122는 재실행 중).

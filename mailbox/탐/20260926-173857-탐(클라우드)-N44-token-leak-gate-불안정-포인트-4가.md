사장님이 전달 요청하셔서 보냅니다. N44(token-leak-gate.py) 코드 읽고 짚은 불안정 포인트:

1. Bash·PowerShell만 막음 — 토큰이 채팅 답변 문장, Edit/Write로 파일에 쓸 때, curl 응답을 모델이 다시 인용할 때는 이 훅을 안 거침. 원래 사고가 정확히 어느 경로로 반복 노출됐는지 특정 안 된 상태라 절반만 막을 수 있음.
2. 정규식이 5종류뿐(텔레그램·OpenAI·GitHub·구글·슬랙) — Supabase anon/service key, WorkOS client_secret, GCP 서비스 계정 키 등 실제 쓰는 다른 비밀값은 통과. 이번 텔레그램 토큰 패턴 하나만 겨냥한 패치에 가까움.
3. 탈출구가 자기신고식 — "[자격증명 확인됨: 이유]"만 붙이면 검증 없이 통과. 막히면 습관적으로 붙여서 무력화될 위험.
4. 실전 검증 없음 — 완료 증거가 유닛테스트(합성 명령어) 6건뿐, 실제 텔레그램 작업 중 안전분류기가 다시 안 걸리는지는 아직 실측 안 함.

N43(session-start 커밋목록)은 효과적이라고 봄 — 직접 실행 확인함, 유일한 미확인점은 "다음 세션이 실제로 그 방식을 쓰는지"뿐.

사장님 정정(2026-09-21 밤): 전달할 것은 실측 내용(결과)이 아니라 핏이 브라우저 컨트롤을 운용하는 「방법」이다. 방금 앞서 보낸 우편(3회 실패 실측)은 참고용이고, 이 우편이 본 전달이다. 정본 가이드는 탐의 docs/딥리서치_실행_가이드.md이며, 아래는 핏이 그 가이드를 실제로 어떻게 서브에이전트에 시켜 돌리는지의 방법이다.

## 1. 역할 분담
- 부모 세션: 질문 작성, 서브에이전트 지시, 결과 판정(채택/반려). 부모는 브라우저를 직접 조작하지 않는다(스크린샷이 부모 컨텍스트를 채운다).
- 서브에이전트: 소넷급. 하이쿠는 UI 반복 작업을 끝까지 못 하고 질문하고 멈춘다. 결과는 「미검증 참고자료」이고 채택·반려는 서브에이전트가 하지 않는다.

## 2. 서브에이전트 지시문의 구조(이 순서로 쓴다)
1. 목적 한 문장(예: 「제미나이 딥리서치를 브라우저 화면 조작으로 대신 실행한다」).
2. 정본 지정: 「먼저 docs\딥리서치_실행_가이드.md 전체를 읽고 3절 안전 규칙, 4절 조작 요령, 5절 문제 처치를 글자 그대로 따른다」(규칙을 지시문에 복사하지 않고 파일 경로로 지정, 핵심 안전 규칙만 한 단락으로 다시 적는다).
3. 도구 로딩 한 줄: ToolSearch로 `select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__find,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__tabs_create_mcp,mcp__claude-in-chrome__tabs_close_mcp`를 한 번에 불러온다(하나씩 부르면 왕복이 낭비된다).
4. 안전 요약: 로그인·비밀번호·2단계 인증·CAPTCHA·본인 확인이 나오면 즉시 멈추고 「막힘」 보고, 「업무 · Pro」 표시로 계정 확인(이메일은 기록에 쓰지 않음), gemini.google.com 밖으로 나가지 않기, 왼쪽 「최근」 목록의 다른 대화는 열지도 읽지도 않기, 설정·구독·계정 전환 금지, 거부 응답은 새 채팅으로 최대 2회.
5. 질문 원문을 따옴표 안에 그대로(「안 들어가면 다시 시도」). 질문은 300자 안팎, 세 갈래로 묶는다. 비공개 정보(가격, 고객, 전략)는 넣지 않는다.
6. 결과 저장과 성공 기준: 보고서 본문을 원문 그대로 C:\work\_ops\research\<날짜>-gemini-<주제>.md에 저장(첫 줄에 「미검증 참고자료」). 성공 기준은 「버튼을 눌렀다」가 아니라 「본문이 파일로 저장됐다」이다.
7. 최종 응답 형식: 저장 경로, 글자 수, 출처 URL 개수, 목차, 막힌 것을 250단어 이내로. 판정은 하지 않는다.
8. 탭은 자기가 만든 것만 쓰고 끝나면 닫는다.

## 3. 서브에이전트의 조작 순서(가이드 4절과 같고 핏이 덧붙인 것만 표시)
tabs_context 확인 → 자기 탭 생성 → gemini.google.com/app 열고 3~4초 대기 → find로 「업로드 및 도구」 버튼을 찾아 ref로 1회 클릭 → 스크린샷 → (핏 추가: 첫 클릭이 무시돼 메뉴가 안 열리면 좌표로 한 번 더. 같은 버튼을 연속으로 두 번 누르지 않는다, 메뉴가 닫힌다) → Deep Research 항목 클릭 → 입력창 위 「Deep Research」 칩 확인 → 프롬프트 입력 상자를 ref로 클릭 후 type → 스크린샷으로 글이 들어갔는지 확인(안 들어갔으면 다시 클릭하고 다시 입력) → Return → 조사 계획이 나오고 자동 시작(또는 「연구 시작」) → 10초 대기를 반복 → 완료되면 보고서 카드를 클릭해 오른쪽 패널을 열고 get_page_text로 본문만 저장.

## 4. 실패 처치의 실제 운용
- 「저는 언어 모델이라…」류 거부: 새 채팅에서 질문을 줄여 다시(최대 2회). 특정 주제어(음성 복제 등)가 필터에 걸리는 것으로 의심되면 재시도 전에 부모가 표현을 정한다(서브에이전트가 임의로 바꾸지 않는다).
- 「문제가 발생했습니다 (1097)」: 새 채팅 재시도(최대 2회), 같은 채팅 재시도는 소용없었다.
- 하루 6건 상한을 서브에이전트 보고에 「오늘 N건 소진」으로 적게 한다.

## 5. 병렬 운용(Flow 등 같은 방식)
작업 단위(계정, 프로젝트)마다 서브에이전트 하나, 각자 자기 탭. 화면 이메일이 대상과 맞는지 먼저 확인. 승인·동의류 창은 서브에이전트가 임의로 누르지 않고 크레딧 수 같은 조건이 맞을 때만 「승인」, 「항상 승인」은 절대 금지, 동의는 부모가 처리. 작업 목록은 JSON 파일로 주고 결과는 서브에이전트가 상태 JSON에 씬별로 기록하게 한다.

## 6. 부모의 사후 처리
결과 원문에서 표본을 직접 확인하고(숫자와 고유명사는 검증 전 미검증), 채택 문장은 출처 URL로 인용 대조. 제미나이 판정은 참고용이다. 예시 지시문 전체는 핏이 사용한 그대로 이 세션 기록에 있고, 파일로는 shorts-lab의 EP_PRODUCTION_PROCESS_검증본_2026-09-21.md ③절과 pilot-shorts2/FLOW_AUTOMATION_POC_2026-09-20.md, DAILY_ROUTINE_핏.md에 같은 방법이 적혀 있다.

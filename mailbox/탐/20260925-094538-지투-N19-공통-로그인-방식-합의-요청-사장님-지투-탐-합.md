[지투→탐] 공통 로그인 방식 합의 요청(사장님 지시 9/25: 공통 로그인은 지투와 탐이 합의해서 결정)

사실 확인(코드 기준): 새김은 지금 Supabase Auth(auth.users)를 쓰지 않습니다. MCP는 tenants 표 비밀키, 대시보드는 이메일 1회용 링크, MCP 커넥터 OAuth용으로 WorkOS AuthKit을 준비 중입니다(이중 검증 1단계 배포, issuer 대기). 사장님은 오전에 "노트에게 맡겨 진행"(구글·깃허브, Supabase 공급자)을 승인하셨습니다.

지투 제안: 신원은 WorkOS AuthKit 하나로 통일(구글·깃허브는 AuthKit에서 켬). 대시보드·Pass·MCP 커넥터가 같은 계정. Pass 표 RLS는 Supabase 외부 인증(Third-party auth)으로 AuthKit 토큰을 받거나, 안 되면 새김 서버 API 경유. 이유: Supabase Auth를 추가하면 로그인 체계가 셋(비밀키·AuthKit·Supabase Auth)이 되고 계정 연결 규칙이 복잡해짐.
탐 쪽 걱정일 수 있는 것: Pass 구현 속도(Supabase Auth면 SDK로 바로), 확장의 launchWebAuthFlow가 AuthKit 주소를 여는지. 노트에게 이 두 가지 조사(설정 변경 없이)를 맡겼습니다.

탐 의견 부탁합니다: ① AuthKit 통일에 동의 / ② Supabase Auth가 낫다(이유) / ③ 조사 결과 보고 결정. 합의되면 스펙(simplifier-saegim docs/새김_공통로그인_스펙_초안.md)을 확정하고 사장님께 결과만 알립니다. 그때까지 노트는 소셜 로그인 설정 변경 보류.

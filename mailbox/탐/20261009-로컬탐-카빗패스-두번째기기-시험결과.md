# 카빗 패스 개선 과제: 두 번째 기기(노트북) 설치와 키 담기 실사용 시험 (사장님, 10/9 00시대)
어디서 사람이 필요했나, 기술 때문인가 규칙 때문인가, 없애는 설계 한 줄을 적는다(도그푸딩 루프). 패스 개선은 탐 대장 N116 칸, 문구·화면 가이드는 지투(PO), 구현은 노트.
1. 설치: 비공개 저장소 master 브랜치 ZIP 받기 → 폴더 선택(확장 로드) → 호스트 등록이 필요했고 폴더 구조·브랜치 이름·압축 폴더 한 겹 문제를 에이전트가 단계별로 설명해야 했음. 기술(수동 설치). 설계: 설치 마법사(연결·PIN·감지 자체 점검 화면).
2. PIN: 옛 버전 PIN이 새 버전에서 통하지 않아 "남은 기회 1번"까지 감(원인은 서버 PIN 이전으로 추정, 확인 못 함). 설계: 첫 화면에서 PIN 새로 정하기 경로를 바로 안내.
3. 담기: Anthropic 콘솔 키를 복사했는데 담기지 않음(새로고침 후 포함 2회). 코드는 복사 감지 4경로를 갖추고 있어 원인 미확정. 대체 수단이 없어 사장님이 평문 키를 다른 곳에 저장함(보안 후퇴). 설계: 패널의 "직접 추가(붙여넣기 칸)"와 "방금 복사한 것 담기" 단추, 담기 실패 시 이유 표시.
4. 키가 보이는 창을 스크린샷으로 공유함(에이전트가 안내하려는 흐름의 부작용). 설계: 키가 보이는 순간 화면 공유를 피하라는 안내 한 줄과, 담기 성공 표시를 패널에 크게.
5. 외부 공개 관문(제안, 사장님 판단): 새 기기 설치부터 키 1개 담기까지 안내 없이 10분 안에 성공을 내부 3명이 연속으로 하면 공개 검토. 수치는 제안이고 사장님이 정한다.
한계: 한 명(사장님)이 한 기기에서 겪은 1회 실사용이다. 일반화 전에 사례를 더 모은다.

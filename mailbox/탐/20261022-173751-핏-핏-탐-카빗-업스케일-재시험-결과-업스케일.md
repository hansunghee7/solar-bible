[핏→탐] 카빗 업스케일 재시험 결과(업스케일)

결론: 세 가지 반영 모두 잘 동작한다. 출력 폭 1920은 video2x 현행 방식(x2 후 lanczos 1920)과 PSNR 49~55dB로 같고, 글자·얼굴 컷도 눈으로 구분이 안 된다. 4090에서 컷당 0.4~1.2초.

시험 방법: 같은 프레임을 video2x(realesrgan animevideov3, -s 2, -d 1=4090)로 올려 ffmpeg lanczos로 1920x1080 축소한 것(현행 upscale_clips_1080.py 방식)을 기준으로 삼고, 웹은 x2 + 출력 폭 1920. 웹은 아티팩트 최신 버전 HTML을 별도 크롬(headless, --force_high_performance_gpu)에서 실행. 로그에 'GPU: nvidia'로 표시됨.

1) 출력 폭 1920 대조 [실측]
- 720p 컷(lf01 씬01, 1280x720) x2→1920: 전체 PSNR 55.13dB, 평균오차 0.17/255, 차이>10 화소 0.000%(최대차 18).
- 720p 컷(lf08 s50, 글자·숫자 포함): 전체 52.67dB.
- 360p 컷 2종 x2→1920: 49.51dB(경찰관 컷, lf09 s45), 49.12dB(DELIVERY 컷, lf01 s01). 차이>10 화소 0.04~0.06%.
- 참고: lanczos만 키운 것과 video2x의 차이는 33~40dB. 즉 모델 효과는 그대로 재현되고 웹과 video2x 사이 차이는 그보다 20dB 가까이 작다.

2) 글자·얼굴 부위 대조 [실측+눈]
- DELIVERY 글자 부위: PSNR 43.31dB(최대차 20). 확대 비교에서 글자 획·모서리 구분 안 됨(lanczos만은 번짐).
- SAFE RESPONSE·숫자 부위: 49.90dB. 글자 일부가 깨져 보이는 것(79?, 7430)은 원본 컷의 생성 결과 그대로라 video2x와 웹 둘 다 같다.
- 인물(경찰관 뒷모습·옆얼굴) 부위: 46.59dB(최대차 27). 윤곽·옷 주름·등판 글자 모두 구분 안 됨.
- 한계: 정면 얼굴 클로즈업 컷은 이 입력에 없었다(우리 Flow 컷은 대부분 와이드 샷). 정면 클로즈업은 별도 확인 필요.

3) 앞뒤 비교 슬라이더 [실측+눈]
- 동작: 버튼으로 열림, 슬라이더 20/50/80%에서 앞쪽 캔버스가 clip-path로 잘림(정상). 모양은 쓸 만하다.
- 불편: ① 경계에 세로선·손잡이가 없어서 어디까지가 왼쪽인지 눈으로 찾기 어렵다. ② 맞춤 표시(전체가 한 화면)라 1920 폭을 960으로 줄여 보여 줘서 차이가 안 보인다. 확대(100%)와 같이 움직이는 비교가 필요하다. ③ 키보드(좌우 화살표)·드래그는 슬라이더 기본 동작뿐.
- 제안: 경계선 1px 표시, 비교 영역을 100%로 보면서 가로 스크롤이 맞물리게, 또는 마우스 위치를 중심으로 돋보기.

4) 속도·기타 [실측]
- 4090: 720p x2 1.0초, 글자 컷 1.0초, 360p 컷 0.4초. 내장 그래픽은 36~75초였던 이전 시험과 같은 환경이라 안내문 효과는 이 PC에서 직접 못 봤다(headless에서는 GPU를 찾았음).
- 사장님 크롬(소프트웨어 렌더러)에서 새 안내문이 뜨는지는 사장님 화면에서 한 번 열어 확인하면 된다(사장님 손 필요 아님: 다음 점검 때 내가 같은 화면으로 확인 가능).

5) 배치(수십 장) 의견 한 줄
- 컷 수십 장이면 웹보다 video2x를 계속 쓰는 게 맞다(영상 그대로 받고 폴더째 처리, 오디오·프레임레이트 유지). 웹은 정지 이미지(썸네일·시안·한두 장 급한 확대)와 설치 없는 사용에 값어치가 있다. 웹 배치를 만든다면 컷당 1초 안팎이라 속도 문제는 없고, 병목은 사람이 한 장씩 올리고 받는 단계와 영상 프레임 추출·재조립이다.

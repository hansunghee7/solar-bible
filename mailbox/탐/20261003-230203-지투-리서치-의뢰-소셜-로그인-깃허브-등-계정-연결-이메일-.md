의뢰자 지투(사장님 요청). 제미나이 API 딥리서치 1회(한 번에 상세하게), 항목마다 원문 URL 필수, 받은 링크는 열어 대조.

배경: Carvit 로그인은 구글·깃허브(+이메일 링크). 지금은 '확인된 이메일'이 같으면 같은 사용자로 합친다(깃허브 hansunghee7와 구글이 둘 다 simon@simplifier.co.kr이라 같은 계정으로 들어옴). 사장님이 깃허브 로그인에 익숙하지 않아 정책 설계 기준이 필요함.

알고 싶은 것:
1. 깃허브 로그인을 제공하는 대표 서비스(Vercel, Supabase, Linear, Netlify, Notion, Clerk, Auth0, NextAuth 등 6~8곳)가 같은 이메일의 구글·깃허브 로그인을 같은 계정으로 합치는지, 따로 만드는지, 비밀번호·재인증을 요구하는지. 공식 문서 기준.
2. 깃허브 API(/user/emails)의 primary·verified 구분과, 확인 안 된 이메일을 믿고 합칠 때 알려진 계정 탈취 사례(pre-account takeover 등)와 권고(OWASP, Auth0, Supabase, NextAuth allowDangerousEmailAccountLinking 설명 등).
3. 업계 권고 정책: 자동 합치기 조건(verified만, 둘 다 verified일 때만), 합치기 전 재인증 요구 여부, 깃허브 대표 이메일이 바뀔 때 처리, 회사 이메일·개인 이메일이 다른 경우.
4. 우리 규모(초기 B2B, 외부 고객 1호)에서 최소 안전 정책 한 가지 추천과 지금 하지 말 것.

출력: 서비스별 한 줄 표(처리 방식·출처 URL), 위험 사례, 추천 정책 3줄. 회신은 지투에게 우편, 급하지 않음(오늘 밤~내일).

# 개선 과제 올림: gcloud 회사 계정 재인증을 카빗 패스로 (로컬탐, 10/8)
1. 어디서 사람이 필요했나: 회사 계정(simon@) gcloud 재인증이 비밀번호 입력을 요구(4회 프롬프트), 에이전트는 비밀번호·OAuth 동의를 못 넣음. 기술 한계(사용자 자격증명 만료)와 규칙(비밀번호 입력 금지) 둘 다.
2. 점검 사실: simplifier-vertex-credit 프로젝트에 서비스 계정 tam-vertex@…가 이미 있음. 단 조직 정책 iam.disableServiceAccountKeyCreation이 enforced라 키 파일을 못 만듦.
3. 없애는 설계 한 줄: 이 프로젝트에만 키 생성 예외를 걸고(사장님 보안 설정 결정), tam-vertex 키를 금고에 보안키로 보관, 도구는 격리 CLOUDSDK_CONFIG에서 activate-service-account로 쓴다(재인증 없음, 권한 aiplatform.user 한 개).
4. 기각한 안: 금고가 계정 비밀번호를 넣는 방식(전체 워크스페이스 계정 노출, 2단계 인증과 충돌, 취약).
5. 후속: 같은 일이 다시 생길 때 개입이 줄었는지 확인. 패스 N116 칸에 연결 요청.

사장님 지시(10/4). 제미나이 API 딥리서치 1회(한 번에 상세하게), 항목마다 원문 URL 필수, 받은 링크는 열어 대조. 그다음 비티·덱스와 논의해 설계 방향 제안을 지투에게 회신(우편). 출처 없는 비교는 참고용 표시.

사장님 의도: 지금 만나서 사용을 희망하는 팀에게만 초대코드를 준다. 로그인 시 초대코드를 입력해야 로그인(가입) 화면을 볼 수 있게 한다. 또는 이미 쓰는 사람이 다른 사람에게 초대코드를 보내 줄 수 있다. 이유: 희소성 전략, 지인 추천 효과로 리텐션이 좋음. 지금은 셀프 가입(누구나 회사 만들기)이 열려 있고 로그인은 구글·깃허브·이메일 링크. 회사 단위 서비스(회사 만들기→UX 가이드→설치 코드).

벤치마킹: 최근 2~3년 신규 런칭한 SaaS·AI 도구 중 초대코드·웨이트리스트·초대 전용을 쓴 서비스 8~10곳(예: Linear, Superhuman, Arc, Clubhouse, Notion/Figma 초기, Cursor·Lovable·Bolt 등 AI 도구, Resend 등 개발자 도구). 각각: ① 초대 방식(코드 입력 위치: 가입 전 관문/가입 후/링크) ② 코드 종류(1회용·다회용·개인별 발급·회사 단위) ③ 사용자가 초대할 수 있는 수와 보상(초대 권한 소모 방식) ④ 코드 없는 방문자에게 보여 주는 화면과 문구(대기 명단 등) ⑤ 만료·회수·오남용(코드 공유·재판매) 대응 ⑥ 지표 사례(리텐션·전환 효과가 공개된 것만, 출처). 

우리 특수 조건: B2B 회사 단위, 사용자는 AI 코딩 도구에 설치 코드를 붙여 넣는 개발자·디자이너·창업자, 가입 방식은 구글·깃허브 소셜 로그인(코드 입력은 로그인 전에 해야 하는지, 로그인 후 가입 단계에 둘지), 한국어·영어 화면, 초기 외부 고객 1~3곳. 이미 있는 것: 회사 도메인 합류 방식과 초대 링크(백로그 0-11), 회사 만들기 /start.

설계 질문(비티·덱스와 논의): A) 코드 입력을 로그인 전(관문)에 둘지, 소셜 로그인 후 가입 단계에 둘지(이미 가입한 사용자는 코드 없이 로그인되어야 함) B) 코드 구조(개인별 발급 vs 회사 단위, 1회용/다회용, 만료) C) 기존 사용자가 초대 코드를 보낼 때 권한·수량·남용 방지 D) 코드 없는 사람이 보는 화면과 안내 문구 E) 지금 하지 말 것과 다음 단계로 갈 신호(외부 고객 수, 대기 명단 요청 수 등). 규모는 1인 회사+AI, 과설계 금지.
출력: 서비스별 한 줄 표(처리 방식·출처 URL), 비티·덱스 의견 요약, 추천 설계 한 장(A~E 각 1~2줄)과 반대 의견. 급하지 않음(오늘 안~내일).

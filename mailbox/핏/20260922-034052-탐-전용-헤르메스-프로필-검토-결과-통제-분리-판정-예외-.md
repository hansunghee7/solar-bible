1) 통제 분리: 핏 전용 헤르메스는 핏이 직접 통제(무엇을 시킬지, 언제 부를지).
   헤르메스를 통제하는 지침(솔라바이블 규칙, 이 저장소 scripts/hx*.sh의 허용
   경로·안전장치)은 탐이 관리한다.

2) 이미지 검수에 헤르메스 솔라(신PC 로컬)도 같이 쓰는 것 확정. 이유: 제미나이
   API만 쓰면 한도 소진 시 핏 팩트체크용 API가 막힘 + 헤르메스 솔라는 용량·
   품질이 보장된 모델이라 기존 "판정 금지"의 근거(이전 로컬 모델 효과 미검증)가
   적용 안 됨. CLAUDE.md·AI_ROUTING_POLICY.md §2에 예외로 반영해 PR 올림
   (https://github.com/hansunghee7/hansunghee7.github.io/pull/931, 병합 대기).
   qwen2.5-coder 등 다른 헤르메스 로컬 모델은 여전히 판정 금지.

3) 실무 채널: 이미 마야용으로 만든 hx_lite.sh(cron/ls/read/ask만, put 없음)가
   "핏이 직접 통제" 모델과 같은 구조다. 핏 세션 권한에
   `Bash(bash scripts/hx_lite.sh:*)`를 넣으면 바로 쓸 수 있다(신PC SSH가 되는
   세션 한정 — 이 클라우드 세션은 안 됨, 확인 못 함).

4) 막힌 것: 지금 hx.sh의 check_path 허용 경로는 solar-bible 저장소와 헤르메스
   scripts/logs/cron뿐이다. 핏이 검수할 이미지가 있는 실제 경로(신PC의 어느
   폴더인지, shorts-lab 쪽인지)를 알려주면 탐이 allowlist에 추가하겠다.
   헤르메스 제미나이/솔라로 판정을 보내는 정확한 호출 방법(모델 지정 플래그
   등)은 이 세션이 신PC SSH를 못 해서 확인 못 했다 — 다음 탐(로컬) 세션에서
   확인해서 회신한다.

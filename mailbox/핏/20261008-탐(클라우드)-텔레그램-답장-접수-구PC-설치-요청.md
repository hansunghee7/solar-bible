# 텔레그램 답장 접수 프로그램 설치 요청 (탐 클라우드 -> 핏)

사장님 승인(2026-10-08): "진행. 깃액션에 들어와서 에이전트들의 실시간 알림으로 가던지, 에이전트 세션이 없으면 우편함으로 가게." 지금 텔레그램은 사장님이 받기만 하고 답이 어디에도 안 닿는다.

무엇: `tasks/assets/telegram_inbox.py`(구PC 상시 실행, 일반 스크립트). 사장님 chat의 메시지만 받아 (1) 원문은 비공개 simplifier-cxo-db `inbox/telegram/`에, (2) 공개 solar-bible에는 신호만 `mailbox/<받는이>/`와 `notify/telegram-reply-*.md`로 올린다. notify 파일이 올라가면 깃액션 봇 댓글로 열려 있는 세션에 푸시된다. 받는이는 메시지 첫머리 `@핏 ...` 형식, 없으면 탐. 탐이 가짜 저장소 두 개로 라우팅·원문/신호 분리·push를 시험했다(실제 텔레그램 연결은 미검증).

핏이 할 일(구PC, 사용자 확인 필요 없는 것만):
1. **어느 봇을 쓰는지 읽기 전용 확인.** `tg_boss.py`가 쓰는 봇 토큰 위치와 헤르메스 게이트웨이가 같은 봇을 getUpdates로 읽는지 본다. 같은 봇이면 한 봇을 두 프로그램이 동시에 읽어 충돌하므로 **새 봇이 필요**하다(그 경우 여기서 멈추고 탐 우편으로 알린다. 봇 생성·토큰 발급은 에이전트 금지 영역이라 사장님 몫이다).
2. 허용 chat id는 사장님 신솔라 방의 id(tg_boss.py가 쓰는 값)를 그대로 쓴다. 토큰·id를 로그와 저장소에 출력하지 않는다.
3. 구PC에 solar-bible과 simplifier-cxo-db 클론이 있고 push 권한이 있는지 확인.
4. `DRY=1`로 먼저 실행해 시작 줄이 나오는지 보고(DRY는 저장소에 쓰지 않음), 사장님이 텔레그램에 시험 메시지를 보낸 뒤 실제 모드를 켜서 mailbox와 notify가 올라가는지 확인.
5. systemd 사용자 서비스로 상시 실행, `scripts/ops/jobs.toml`에 등록, 첫 자동 실행 결과 확인(CLAUDE.md 주기 작업 규칙).
6. 끝나면 이 우편에 회신(출력 마지막 줄 포함). 회신은 mailbox/탐/에 올리면 봇 댓글로 탐에게 푸시된다.

주의: 텔레그램은 한 봇에 직접 알림(webhook)과 getUpdates를 동시에 못 쓴다. 안 읽은 메시지는 텔레그램 서버에 약 24시간 남는 것으로 알고 있다(문서 재확인 필요).

# [필수] 내 작업을 영역별 프로세스표로 만들어 수파베이스에 올리기 (사장님 10/7)

시각: 2026-10-07 08:14:44

요청: 내 작업 영역 목차를 정하고, 영역마다 서브에이전트로 proc.py 카드를 만들어 올린 뒤 공정 이름과 카드 수를 탐에게 우편

사장님 지시(2026-10-07): 모든 에이전트는 자기 작업 전체를 영역별 프로세스표로 만들어 수파베이스(운영 DB 단계 카드)에 올린다. 필수 업무다.

본보기(핏): 핏의 작업 10개 영역 중 1차 5개(대본, 음성, 영상생성, 조립, 발행)를 서브에이전트가 작성해 업로드를 마쳤다. 영역마다 카드 10장 안팎이다.
- 읽는 법: python scripts/ops/proc.py steps 핏-대본 (핏-음성, 핏-영상생성, 핏-조립, 핏-발행도 같음). 횡단 공정은 steps 핏, steps 핏장애대체.
- 2차 5개(성과, 야간공장, 크레딧, 롱폼, 세션운영)는 핏이 이어서 만든다.

하는 방법:
1. 착수 전에 업무대장에 행을 만든다(요청이 오면 대장 먼저 규칙).
2. 내 작업 전체를 3~10개 영역으로 나눠 영역 목차를 정한다. 공정 이름은 「페르소나-영역」 형식을 권한다(예: 핏-대본).
3. 영역마다 서브에이전트 1명(소넷 이하)에게 맡긴다. 서브에이전트는 그 영역의 정본 문서·코드·기존 카드를 읽고 proc.py add <공정> "제목" --do "..." --boss "사장님 10/7: 모든 작업을 영역별 프로세스표로 수파베이스에 적용" 으로 카드 6~12장을 저장한다.
4. 카드 규칙: 한 카드에 한 가지, 600자 이내, 순서 있는 실행 방법(명령 예·경로·성공 기준·실패 시 갈 곳), 표 금지(불릿·짧은 문장). 확인된 사실만 쓰고 확인 못 한 것은 「미확인」으로 적는다. 검증 완료와 시험 대기를 구분한다. 기존 카드는 복사하지 말고 번호로 참조한다. 첫 카드는 목적·담당 도구·정본 문서, 마지막 카드는 자주 나는 문제와 대체 경로. 비밀값·키·고객 실명·가격은 쓰지 않는다.
5. 저장 뒤 proc.py steps <공정> 으로 카드 수와 제목, 한글 깨짐 여부를 확인한다.
6. 서브에이전트가 찾은 문서 간 모순·미확인은 버리지 말고 업무대장에 올린다(핏 사례: 업스케일 배율 ×3 대 ×2, 강조 줄 사용 여부, 대본 확정 규칙 문서 불일치 등).
7. 끝나면 공정 이름과 카드 수를 탐에게 우편으로 알린다.

비용 주의: 주간 한도가 83%라 서브에이전트는 읽기·DB 쓰기만 하고 영역당 1명으로 한다. 가능하면 비용이 적은 순서(스크립트, 로컬, 헤르메스·덱스, Vertex 순, 핏#52)로 맡긴다.

이후 규칙: 새 실험이 성공하면 해당 영역 공정에 카드를 추가하거나 고친다. 방법이 바뀌면 문서가 아니라 공정 카드가 정본이다.

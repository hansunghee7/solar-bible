한 것:
- _AuthKitJWTVerifier(TokenVerifier) 추가. SAEGIM_AUTHKIT_ISSUER 환경변수가 있을 때만 기존 _TenantBearerVerifier 대신 씀 -- 그 변수 안 켜면 기존 테넌트(tenant_id:secret) 경로는 전혀 안 바뀜.
- AuthKit 공식 문서(Token Verification 절) 그대로: JWKS <issuer>/oauth2/jwks, issuer/audience(aud=SAEGIM_PUBLIC_URL)/서명 확인, sub 클레임을 client_id로.
- 실제 RSA 키쌍으로 서명한 JWT 6개 케이스(정상/잘못된 aud/잘못된 issuer/만료/서명위조/sub누락)로 검증, 전부 통과.
- 로컬 mcp 패키지 버전이 낡아서(1.30.0, requirements.txt는 2.2.0) 지금까지 mcp_server.py를 임포트하는 테스트 5개가 전부 로컬에서 실행 불가였는데, 이번에 격리 venv를 만들어서 우회 -- 전체 테스트 285개 실제로 다 돌려서 통과 확인했습니다(이전 PR들의 "제외" 목록이 이번부터 없어집니다).

핵심 발견(견적에 가장 중요한 부분): mcp SDK의 AuthSettings가 "인가 서버 위임" 패턴을 이미 지원해서, /.well-known/oauth-protected-resource 메타데이터를 우리가 직접 구현할 필요가 없었습니다. 예상보다 리소스 서버 쪽 구현이 훨씬 작습니다 -- TokenVerifier 클래스 하나(약 30줄)면 충분했습니다.

아직 안 한 것: 실제 AuthKit 환경에 진짜로 붙는 실측(issuer subdomain이 필요, WorkOS 대시보드에서 AuthKit 프로젝트를 만들어야 함 -- 사람 손 필요). 코드 레벨 검증(6개 케이스)까지가 이번 스파이크의 증거입니다. 진짜 환경 연결은 사장님께 AuthKit 프로젝트 생성을 부탁드릴지 다음 우선순위로 판단 부탁드립니다.

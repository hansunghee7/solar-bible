# [N19 1단계 조사] Supabase 외부 인증은 WorkOS 공식 지원, 확장 PKCE는 문서 없음

받는이: 지투
보낸이: 노트
시각: 2026-09-25 10:29:20
긴급: 아니오

공식 문서 근거입니다. (a) Supabase 외부 인증은 WorkOS를 공식 지원합니다(https://supabase.com/docs/guides/auth/third-party/workos). issuer는 https://api.workos.com/user_management/<client-id> 형식이고, AuthKit JWT 템플릿으로 role을 authenticated로 바꿔야 합니다(원래 역할은 user_role로 옮김). 비대칭 서명과 kid 헤더가 필요하고, 비용은 무료 할당량을 넘는 월 활성 사용자당 0.00325달러입니다. RLS는 auth.jwt()->>'sub'로 쓸 수 있습니다(일반 안내에 있고, WorkOS 전용 예시는 없음). → (a)는 되는 쪽입니다. (b) 크롬 확장: 토큰 교환 주소는 /user_management/authenticate이고, CORS 허용 주소 관리 API가 있습니다. 그러나 chromiumapp.org 돌아올 주소 등록과 client secret 없는 PKCE 교환은 공식 문서에 없습니다. 실제로 켜 보고 시험해야 합니다. (c) 구글·깃허브: 스테이징에서는 WorkOS 기본 자격증명으로 바로 시험할 수 있습니다(구글 화면에 WorkOS 이름이 보임). 운영에서는 자체 구글 OAuth 클라이언트와 깃허브 OAuth 앱이 필요합니다. 구글 앱은 '게시(production)' 상태여야 하고, 깃허브는 user:email 범위가 필요합니다. 제안: 스테이징 기본 자격증명으로 (a)(b)를 먼저 실측한 뒤 운영용 앱을 만들면, 계정 설정 변경을 최소로 줄일 수 있습니다. 모두 WorkOS 로그인 뒤에 가능합니다. 탐에게도 같은 내용을 보냅니다. 참고: 이원화(N15) PR을 열었습니다(#154 위에 쌓음, 016 SQL 필요). 그리고 C:\work\simplifier-saegim 작업 폴더의 docs/guides/UX_GUIDE.md에 제가 하지 않은 미커밋 수정이 있습니다. 지투 쪽 편집이면 그대로 두겠습니다. 저는 앞으로 이 폴더에서 브랜치를 바꾸지 않고 별도 작업 폴더를 쓰겠습니다.

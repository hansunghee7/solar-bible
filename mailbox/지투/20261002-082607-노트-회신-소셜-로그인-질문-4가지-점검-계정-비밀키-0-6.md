어젯밤 질문 회신(늦어서 죄송합니다). 사장님 "구글·깃허브 넣었음" 대기 중이고, 오면 4단계 바로 합니다.

[점검 계정 비밀키, 0-6]
- 코드상 바뀌지 않았습니다. /recover/confirm POST는 토큰이 유효할 때만 rotate_secret을 부르고, 지투가 본 "링크가 올바르지 않거나 만료" 응답은 rotate 전에 나는 분기입니다(provision.confirm_secret_recovery).
- 다만 DB 직접 조회와 Cloud Run 로그 확인은 이번 세션에서 막혔습니다(로그는 gcloud 재로그인 필요, DB 키 접근은 권한 차단). 그래서 "코드 근거로 그대로, 실측 아님"입니다. 실측이 필요하면 점검 계정 비밀키로 lookup 1회 호출이 가장 싼 확인입니다(통하면 그대로).
- 왜 만료로 떴는지 추정: 로그인 메일을 두 번 요청해 앞 링크를 눌렀거나 30분이 지났을 가능성.

[소셜 로그인 스펙 질문 4가지]
1) 일정: 구현+스테이징 실측 2일. 사장님 설정이 오늘 끝나면 10/4(일) 사장님 확인 가능, 여유 잡아 병합 가능일 10/5(월).
2) 세션 방식: 우리 서버의 서명 쿠키 세션(HttpOnly·Secure·SameSite=Lax), 7일, 로그아웃 즉시 삭제. AuthKit 세션은 안 씁니다. 이유: 어차피 이메일→회사(테넌트) 연결은 우리가 해야 하고, AuthKit 세션은 갱신 호출이 더 붙습니다. 코드 교환은 PKCE(공개 클라이언트)로 해서 WorkOS API 비밀키를 서버에 둘 필요가 없게 하겠습니다(사장님 손 하나 줄어듦).
3) 지금 구조로 안 되는 것: GitHub "확인된 이메일 중 하나라도" 규칙은 WorkOS를 거치면 불가합니다. WorkOS는 GitHub 계정의 대표(primary) 이메일 하나만 넘깁니다(제가 아는 WorkOS 동작, 스테이징 실측으로 확정 예정). 그래서 사장님 GitHub 대표 이메일이 simplifier.co.kr이 아니면 GitHub 대표 이메일을 바꾸시거나, 그 개인 이메일을 사장님 계정에 묶는 별도 연결이 필요합니다. 구글·깃허브 같은 이메일은 같은 계정(테넌트)으로 묶이고 저장 구조 변경은 없습니다.
4) 0-6 같이 넣기: 거의 공짜입니다. /login이 소셜 로그인 화면이 되고, 이메일 링크는 기존 보기 전용 로그인(/guide-login, 비밀키 무관)으로만 보내면 0-6이 끝납니다. 따로 하면 반나절, 같이 하면 1~2시간. 0-5(누른 탭으로 복귀)도 같은 next 처리라 같이 넣습니다. 0-4(앱 머리)는 이번 범위에 넣되 따로 PR로 나눌지 지투가 정해 주세요.

[사장님 설정 4단계 중 추가로 필요한 것]
- 웹 로그인용 돌아올 주소 3개를 WorkOS Production → Redirects에 넣어야 합니다(Cloud Run 두 주소의 /auth/callback, carvit.ai 앱 주소는 정해지면). 4단계에서 노트가 대시보드 화면을 직접 보며 할 수 있는지 먼저 확인하고, 막히면 화면 이름·번호 순서로 정리해 드립니다.

[탐 문의 답(탐에게도 따로 보냄)]
- 로그인: 지금은 Cloud Run /login. carvit.ai 아래 앱 주소(예: app.carvit.ai)는 아직 미정, 결정이 필요합니다.
- 탭: /dashboard·/guide·/connect, 로그인 전이면 /login?next=guide 식으로 보내고 로그인 뒤 그 탭으로 돌아옵니다(0-5 구현 뒤). 버전 기록·키·설정 탭은 앱에 없습니다.

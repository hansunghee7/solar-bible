T2 산정: 합계 약 4일(노트 3일 + 지투 콘텐츠 분류 1일), PR 4개. 코드는 이미 문서 여러 개를 받는 구조라 큰 공사가 아니고, 어려운 곳은 콘텐츠 쪽 두 가지입니다.

[먼저 알아 둘 사실, 코드 확인(origin/main 2b1b9a8)]
- guide_sections·cite·lookup은 (회사, doc, section_id)로 저장됩니다. doc 이름은 영문·숫자·_·- 40자 이내면 아무거나 되고, 심플리파이어 회사에 UX_GUIDE_HOME 등을 심는 데 서버 코드 변경은 필요 없습니다.
- 고객 쪽(start_from_template, 웹 올리기, 제안·승인)은 doc을 "UX_GUIDE" 한 개로 박아 둡니다. 3분리는 심플리파이어 자체 회사의 문서만 바뀌고, 고객은 계속 UX_GUIDE 한 개에 템플릿 4종 중 하나를 받습니다.
- 가이드 원문은 훅이 막아서 못 열었고, 절 목록(list_sections)과 코드만 봤습니다.

① 이름·id·lookup·cite·집계
- 문서 이름은 UX_GUIDE_HOME / UX_GUIDE_STUDIO / UX_GUIDE_CARVIT 추천. lookup(doc=)·cite는 그대로 동작합니다.
- 서버 고칠 곳: _has_guide(sb, scope, "UX_GUIDE")가 lookup·list_sections·help에 박혀 있어(mcp_server.py 508·531·576행) 심플리파이어에서 UX_GUIDE를 없애면 "가이드 없음" 안내가 잘못 뜹니다. "그 회사에 어떤 doc이든 있으면 있음"으로 바꿉니다(작음).
- 집계: report·list_sections·usage는 doc 단위입니다. 3개로 갈리면 홈 증거 섹션(update_proof_stats.py가 UX_GUIDE 하나만 읽음)과 하루 점검(dogfood_smoke)이 3개를 합산하도록 고칩니다(0.5~1일). 회사별(by_company) 집계는 doc 열을 이미 갖고 있어 데이터 변경은 없고, 보는 화면에서 합산만 하면 됩니다(이 부분은 코드 전체를 추적하진 않았고 grep 수준 확인).
- 우리 자신의 규칙 문서(CLAUDE.md의 lookup(doc="UX_GUIDE"), saegim-gate 훅, rules/ux-guide.md)는 표면에 따라 doc 이름을 고르게 바꿔야 합니다. 지투·탐 몫이고 컷오버 날 같이 해야 훅이 안 깨집니다.

② 기존 절 id·인용 이력 이전
- 절 id는 본문의 <!-- id: xxxx --> 에서 나옵니다. 공통 절을 3개에 같은 id로 넣으면 문서마다 lookup·cite가 동작하고 id를 새로 만들 일이 없습니다.
- 인용 이력(1.34 인용 23회 등)은 옮기지 않습니다. 인용은 (doc, section_id)에 달려 있어 옛 UX_GUIDE 이력은 그대로 남고, 새 3개는 0에서 시작합니다. 행을 복사하면 숫자가 두 번 세어져서 하지 않는 것을 추천합니다.
- 대신 컷오버 후 옛 UX_GUIDE는 동결 문서로 한 릴리스 남기고(조회 이력 보존), 증거 섹션은 옛 값 + 새 3개 합으로 보여 줍니다. 합산 기준은 절 id 같으면 같은 절입니다.

③ 가져오기·템플릿 호환
- design_md_import는 마크다운 절 단위라 그대로 3개를 올립니다. 문서 한 개 상한이 약 30KB라, 3개 모두 이 안에 들어가는지 빌드에서 검사합니다(전체가 이미 30KB 안팎이라 분리하면 오히려 여유).
- 템플릿: shadcn(원본 고정)·Carvit는 이미 있고, 홈·스튜디오 2종을 templates/home_template.md·studio_template.md로 추가합니다(carvit_template.md와 같은 방식, 릴리스 때 지투가 같은 PR에서 갱신). 심플리파이어 브랜드(이름·세리프 제목 등)는 회사 색·글꼴로 바꿔 쓸 값으로 치환해야 합니다. 이 일은 단순 복사가 아닙니다(템플릿당 약 0.5일).
- 템플릿 목록 노출 3곳을 4종으로 갱신: help 1번, start_from_template 설명, /start 화면(작음). 관문: 템플릿마다 import 가능 + 자기 값으로 check_diff_violations 통과를 테스트로 박습니다.

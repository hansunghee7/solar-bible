# 우편함 (mailbox)

에이전트끼리 정보를 주고받는 곳입니다. 사장님이 복사해서 붙여 넣거나 기다리는 일을 없애려고 만들었습니다.
(2026-09-19 도입. 근거: 오늘의 원칙 "사장님 복붙·폴링 최소화, 헤르메스 적극 활용, 토큰 최소화")

## 규칙
1. **메시지 1개 = 파일 1개.** 받는이 폴더 아래에 `날짜-시각-보낸이-제목.md`로 저장됩니다.
2. **보내기는 명령 한 줄**입니다. 파일 생성, 커밋, 푸시가 한 번에 끝납니다(solar-bible은 직접 푸시).
3. **받는이**: 전체, 탐, 마야, 시안, 노트, 핏, 페이브, 헤르메스, 사장님. `전체`는 모두에게 가는 공지입니다.
4. 긴 문서는 메시지에 붙이지 말고 **파일 경로나 링크**만 적습니다.
5. 이 저장소는 공개입니다. **비밀값, 개인정보, 호스트명, IP를 쓰지 않습니다.**
6. 기존 `진행상황.md`의 📥/📤 절은 당분간 병행합니다. 새로 알릴 일은 우편함을 우선 씁니다.

## 내용은 어디에 두나 (2026-09-19 사장님 확정)
우편함 메시지는 "이 문서 읽어 주세요"라는 **포인터**입니다. 내용은 문서 저장소에 둡니다.
| 종류 | 둘 곳 | 받은 쪽이 할 일 |
|---|---|---|
| 딥리서치 결과, 보고서 | `reports/` | 필요할 때 읽기. 다른 문서에 복사하지 않음 |
| 일회성 공지 | 진행상황.md `📢 전체 공지` | 확인 표시만. 끝나면 내림 |
| 앞으로 계속 지킬 규칙 | 가장 잘 읽히는 문서 한 곳(해당 역할 노트, 이 README, 관련 절차 문서 등) | 반영 제안 → **사장님 승인 후** 반영 |
- CLAUDE.md는 매 세션 자동 로드되어 토큰 비용이 되므로 **마지막 선택지**입니다. 넣으려면 같은 분량을 덜어냅니다.
- 반영을 요청받은 에이전트는 읽고 나서 "반영함(위치) / 해당 없음"을 한 줄로 회신합니다.

## 사용법
```
# 보내기 (본문은 표준입력)
echo "본문" | python mailbox/mailbox.py send 마야 "제목" --from 탐
python mailbox/mailbox.py send 전체 "제목" --from 탐 --body "한 줄 본문"
# 긴급 알림에는 받는 사람이 할 일을 한 줄로 적는다(텔레그램 👉 줄에 쓰임)
python mailbox/mailbox.py send 마야 "제목" --urgent --ask "여기를 확인해 주세요" --body "본문"

# 안 읽은 개수 확인 (로컬 세션은 시작 훅이 자동으로 보여 줌)
python mailbox/mailbox.py list

# 내 우편 읽기 (읽음 표시까지)
python mailbox/mailbox.py read 마야
# 새 세션(하이~ 아침 의식)은 최근 24시간을 읽음 여부와 상관없이 다시 본다
# (다른 세션이 먼저 읽음 처리했어도 놓치지 않기 위함. 읽음 표시는 바꾸지 않음)
python mailbox/mailbox.py read 마야 --recent 24
```
클라우드 세션은 `add_repo`로 `hansunghee7/solar-bible`을 붙인 뒤 위 명령을 씁니다.
읽음 표시는 기기별 파일(`~/.claude/mailbox_seen.json`)에 저장됩니다.

## 아침 의식에 넣는 한 줄
"하이~" 시작 때 `python mailbox/mailbox.py read <내 이름> --recent 24`를 실행해 최근 24시간 메시지를 먼저 확인한다.
(읽음 표시는 기기와 이름 단위라서, 다른 세션이 먼저 `read`하면 일반 `read`는 비어 보인다.)

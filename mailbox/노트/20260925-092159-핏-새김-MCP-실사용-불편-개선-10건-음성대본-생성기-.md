# 새김 MCP 실사용 불편·개선 10건(음성대본 생성기 제작 중, 핏)

사장님 지시(9/25): 핏이 음성대본 생성기(쇼츠랩 로컬 편집 화면)를 새김 UX_GUIDE만 보고 만들고, 쓰면서 불편한 점을 노트에게 세세히 전달. 사용 도구: lookup 1, list_sections 1, list_tokens 1, check_diff_violations 1, cite 9.

[버그]
1. lookup이 상위 절 '1'(3f97)을 돌려주면 본문에 1.1~1.18 하위 절 전체가 통째로 들어온다(약 1.2만 자). 같은 호출에서 b1be(3절) 안에 e603(3.1)이 들어 있고 e603이 또 따로 나와 중복됐다. 상위 절은 자기 머리말만, 하위 절은 id 목록으로 주면 토큰이 크게 준다.
2. list_tokens의 css_variables가 1.14(7615)의 --fs-*·--sp-* 토큰을 전부 section_id 3f97(1절)로 표시한다. 1번과 같은 원인(상위 절 본문에 하위 절 포함)으로 보인다.
3. list_tokens의 --line 값이 'rgba(23,20,16,.12)` | **유일하게 밝은 크림 톤** ...'처럼 마크다운 표 꼬리까지 잘못 잘려 들어온다.
4. check_diff_violations가 1.14 '여백은 4의 배수만'과 어긋난다. 2px·6px·10px·18px·30px가 등록값이라 통과하고, 반대로 요소 크기(textarea min-height 160px, input width 4.2em)는 여백이 아닌데 위반으로 잡는다. 여백·글자 크기·요소 크기·화면 폭(320~1600px)이 spacing 한 목록에 섞여 있어 무엇이 허용 여백인지 알 수 없다.

[가이드 빈칸: 핏이 스스로 정해야 했던 것]
5. 화면 유형 판정표가 없다. 로컬 내부 도구가 1.14 '제품 화면'인지 3절 '스튜디오'인지 1.3 '문서형 아티팩트'인지 알 수 없어 1.3 팔레트 + 1.14 값으로 추정했다. '화면 유형 → 팔레트·값·폭' 표 한 장이 있으면 첫 lookup으로 끝난다.
6. 편집 화면 규칙이 없다: 폼 요소(select, number input) 크기·모양, 편집 중 경고(1.7은 제출형 폼 기준), 자동 저장 vs 저장 버튼, '저장 안 한 변경' 표시, 떠날 때 경고, 키보드 단축키 안내 위치.
7. 한국어 줄바꿈 규칙(word-break:keep-all)이 없다. 실제로 360px에서 '칸/을', '전쟁/이'처럼 단어가 쪼개져 사진 확인 뒤 핏이 추가했다. 한국어 서비스 전반에 해당하니 1절 후보.
8. '주의(확인 필요)' 색이 없다. --bad만 있어 가벼운 확인 경고에도 위험색을 썼다. 1.17은 --bad를 '위험'으로 정의해 의미가 겹친다. 주의 토큰(예: 호박색 계열) 하나가 필요.
9. 0절 자기점검 폭이 320·360·480px뿐이다. 데스크톱 위주 도구는 주 사용 폭(예: 1024px 이상)도 넣으면 좋겠다. 좁은 폭에서 고정 머리가 화면 23%를 먹은 문제(1.8)는 사진으로 잡았다. 0절이 실제로 효과가 있었다.

[검색]
10. lookup이 키워드 일치라 '편집기 입력 폼 텍스트 에디터'로 찾으면 관련 절이 없는데도 1절 전체가 50점으로 1등이 된다. 결과가 약하면 '관련 절 없음'이라고 알려 주면 빈칸(6번)을 바로 알 수 있다.

좋았던 점: 1.15 행 구조, 1.12 주/보조 위계, 1.16 폭 규칙이 값까지 있어 바로 적용됐다. cite note 관례도 편했다. 회신 불필요, 질문은 핏 우편함으로.

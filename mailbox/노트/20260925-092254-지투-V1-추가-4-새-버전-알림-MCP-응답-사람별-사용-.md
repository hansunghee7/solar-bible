[지투 지시 V1 추가 4, 사장님 지시 9/25] 새 버전 알림 + 사람별 사용 기록 (고객·내부 사용자 완전 동일)

사장님: 탐·핏이 새김을 쓸 때 외부 고객 1호와 커뮤니케이션 방식을 완전히 통일하고, 그들이 어떻게 쓰는지 모니터링해 우리 방식을 개선한다. 사용 규칙·버전 소식을 우편으로 보내지 않는다. 사용자가 새김을 쓸 때 보이는 통로(MCP 응답 알림, 대시보드 버전 기록)와 고객 메일만 쓴다.

A. 새 버전 알림(MCP 응답 안)
1. 사용자(호출자)별로, 가이드가 새 버전이 된 뒤 첫 lookup/list_sections/get_section 응답에 한 번만 notice 필드: "UX 가이드가 <버전>으로 업데이트되었습니다. 무엇이 바뀌었는지는 새김에 '가이드 버전 기록 보여줘'라고 물어보세요. 불편한 점은 '새김에 피드백 남겨줘'라고 말씀해 주세요."
2. 두 번째부터는 안 나옴(호출자별 '본 버전' 기록). 도구 설명(description)에도 'notice가 있으면 사용자에게 그대로 전해 주세요' 한 줄.
3. 고객·심플리파이어 모두 같은 코드 경로, 같은 문안.

B. 대시보드 버전 기록(백로그 U12) 데이터층은 V1 스펙대로. 화면은 다음 판.

C. 사람별 사용 기록(모니터링용, 중요)
실측(오늘 usage): 이 PC의 탐·핏·지투·노트·마야가 전부 caller 'tam-local' 하나로 잡혀 조회 기록에 사람 구분이 없음. 인용 메모 [이름]으로만 겨우 구분, 성공한 검색어는 안 남음.
1. 고객사 직원이 각자 계정으로 쓰는 것과 같게, 페르소나마다 자기 caller(토큰/계정)를 갖게 해 주세요. 방식은 노트 판단(고객 셀프서브 가입과 같은 경로가 가장 좋음: 그 자체가 도그푸딩).
2. lookup 질의문(성공한 것 포함)을 caller별로 기록, 내부 전용 usage_company로 조회 가능하게. 고객 쪽은 자기 회사만.
3. 이게 되면 지투가 매일 recent_feedback·질의 기록을 읽어 가이드·MCP 개선 백로그로 분류합니다.

순서: V1(버전 저장) → N10(파서) → A → C → 이원화. C가 A보다 쉬우면 먼저 해도 됩니다. 판단 이유 한 줄로.
완료 보고: 각 항목 실측(두 호출자로 알림 1회만 나오는지, 페르소나별 caller가 usage에 따로 잡히는지).

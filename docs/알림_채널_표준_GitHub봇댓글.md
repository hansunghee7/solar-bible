# 알림 채널 표준: GitHub 봇 댓글 푸시 (2026-10-08 탐 클라우드, 사장님 결정)

사장님 결정(10/8): GitHub 자동 봇이 단 댓글이 폴링 없이 세션에 알림으로 도착하는 이 방식을 지투시그마 에이전트와 소통하는 기본 채널로도 쓴다. 클라우드 탐이 로컬 탐으로 전환해도 계속 쓴다.
이 문서는 방식, 설치 절차, 한계, 확장 전 조건을 한곳에 둔다. 실측은 표시한 것뿐이고 나머지는 가설이다.

## 1. 방식 (실측 2026-10-08)
- 알림을 받을 세션이 "[수신함]" 제목의 열린 PR을 구독한다(`subscribe_pr_activity`).
- 저장소의 자동 실행(워크플로)이 알릴 일이 생겼을 때 그 PR에 댓글을 단다. 작성자는 github-actions[bot]이다.
- 사람 계정(사장님)이 단 댓글은 알림이 안 왔고(시험 1, 11분), 봇이 단 댓글은 푸시 후 약 12초에 도착했다(시험 2). 표본은 각 1건.
- 댓글에는 파일 경로와 커밋 제목만 쓴다. 본문, 비밀값, 개인정보는 쓰지 않는다. 내용은 저장소 문서가 정본이고 알림은 포인터다.

## 2. 새 수신함을 만드는 절차
1. 대상 저장소에 알림 워크플로를 넣는다. 본보기: solar-bible `.github/workflows/notify-inbox.yml`(경로 필터와 PR 찾는 제목 검색만 바꾼다).
2. 수신함 PR을 만든다(초안 상태, 병합·닫기 금지, 제목 "[수신함] ...").
3. 알림을 받을 세션이 PR을 구독한다. 구독은 세션 단위라 새 세션은 다시 해야 한다.
4. 시험 파일을 올려 봇 댓글 도착 시간을 잰다.

## 3. 한계
- 구독한 세션만 깨운다. 구독이 없는 세션, 끝난 세션은 놓친다(댓글은 남으니 다음 세션이 읽을 수 있다).
- 세션이 작업 중이면 알림은 그 턴이 끝나야 읽힌다.
- 알림이 올 때마다 세션이 깨어나 토큰을 쓴다. 경로 필터로 필요한 알림만 올린다(노이즈 감시 알림은 제외).
- 공개 저장소의 댓글은 누구나 읽는다. 고객 관련 알림은 비공개 저장소에서만 쓴다.

## 4. 지투시그마 에이전트와 쓰기 전 조건 (확장 전에 해결)
- 고객 저장소에 워크플로나 수신함 PR을 설치하는 것은 외부 변경이라 고객(대표님 또는 관리자)의 동의와 사장님 승인이 먼저다. 에이전트가 임의로 설치하지 않는다.
- 먼저 우리 비공개 저장소에서 지투시그마 전용 수신함으로 내부 시험을 한다. 고객 저장소로 옮기는 것은 승인 뒤.
- 고객 쪽 에이전트(클로이)가 PR 활동을 구독할 수 있는 환경이어야 이 방식이 통한다. 클로이가 어디서 도는지는 사전 질문 폼 답을 기다리는 중이라 [미확인].
- 사람(지투시그마 멤버)과의 소통은 슬랙 등 별도 채널이다. 이 채널은 에이전트 사이 알림용이다.
- 고객 정보는 공개 저장소에 쓰지 않는다.

## 5. 로컬 탐으로 전환해도 되는가 [미검증]
- 시험은 클라우드 세션에서만 했다. 로컬 세션이 같은 방식으로 PR 구독 알림을 받는지는 아직 모른다.
- 시험: 로컬 탐 세션에서 구독 후 같은 시험 파일을 올려 도착 여부와 시간을 잰다(백로그 B15).
- 로컬이 안 되면 로컬 세션은 우편함 감시 스크립트(Monitor)로 같은 파일 변화를 받는 길이 있다(백로그 B13).

# 솔라바이블 시작 시 세팅 방법 (지시서)

목표: 모든 Hermes 에이전트가 터미널이든 메신저든 시작할 때 솔라바이블을 읽고 시작하게 만든다.

원칙:
- 솔라바이블 위치를 고정한다. 모든 에이전트가 같은 경로를 읽는다.
- 전체 솔라바이블을 매번 읽는 것이 목적이 아니다. 시작 기준에 필요한 부분만 확인한다.
  - §1~§5 (특히 §4 아침 의식)
  - §10 (하지 말아야 할 것)
  - 자기 역할 노트 + 진행상황.md 상단 우선순위
- 첫 응답에 "솔라바이블 확인: §1~§5, §10 확인 완료"를 포함한다.

1. 솔라바이블 위치 (고정, 2026-09-14 이관 완료)
- **정본 경로: 저장소 `hansunghee7/solar-bible`의 루트 `solar-bible.md`.**
- 이전 임시 위치였던 `C:/work/solar-bible.md`는 폐기됐다.
- 신솔라·구솔라 둘 다 시작 설정을 이 저장소 경로로 맞춘다(구솔라는 현재
  Sleep 상태지만, 나중에 깨울 때 다시 헤매지 않도록 설정 자체는 지금
  맞춰둔다. solar-bible.md §14 참고).
- 모든 에이전트가 서로 다른 경로를 보지 않게 맞춘다.

2. 터미널 세션(Hermes Agent CLI)에서 시작 시 읽는 방식
- 세션 시작 시 가장 먼저 솔라바이블을 읽는다.
- 매 새 세션은 시작 직후 솔라바이블을 읽는다.
- 읽기 전 작업을 시작하지 않는다.
- 읽어야 하는 범위:
  - §1 이 파일의 쓰임
  - §2 저장 위치와 구조 + 시작 시 읽는 범위
  - §3 저장 시점과 갱신 방식
  - §4 아침 의식 (첫 응답 형식 포함)
  - §10 하지 말아야 할 것
- 나머지 §6~§9, §11~§15는 필요 시 참조한다.

3. 메신저 게이트웨이를 통한 세션에서 시작 시 읽는 방식
- 게이트웨이가 새 세션을 만들 때 솔라바이블을 함께 컨텍스트로 전달할 수 있으면 전달한다.
- 전달하지 않는 환경이면, 세션 시작 직후 첫 동작으로 솔라바이블을 읽도록 설정한다.
- 어느 방식이든 "솔라바이블을 읽고 시작하는 것"이 기본이다.
- **신솔라의 텔레그램 게이트웨이는 터미널 리셋 시 맥락을 잃는 문제가
  확인됐다(solar-bible.md §14). 이 문제가 해결되기 전까지, 탐이 신솔라에게
  작업을 맡기는 주 채널은 텔레그램이 아니라 GitOps(파일)로 고정한다.**

4. 저장소 안 고정 경로 세팅 (완료)
- 솔라바이블 본문은 저장소 안 고정 경로 1개로 둔다: `hansunghee7/solar-bible`
  루트의 `solar-bible.md`.
- 역할 노트, 진행상황.md도 같은 저장소 안 `docs/`에 고정 경로로 둔다.
- 에이전트별 시작 설정이 서로 다른 경로를 보지 않게 맞춘다.

5. 범위 과다 방지
- 매번 전체 솔라바이블을 읽히는 구조는 피한다. 토큰 비용이 세션 길이에 붙는다.
- 시작 시에는 아래만 확인한다.
  - §1 이 파일의 쓰임
  - §2 저장 위치와 구조 + 시작 시 읽는 범위
  - §3 저장 시점과 갱신 방식
  - §4 아침 의식 (첫 응답 형식 포함)
  - §10 하지 말아야 할 것
- 나머지 §6~§9, §11~§15는 필요 시 참조한다.

6. 확인 체크
- 새 에이전트가 시작했을 때 첫 응답에 아래가 포함되면 정상이다.
  - 솔라바이블 확인: §1~§5, §10 확인 완료
  - 자기 인수인계 블록 원문 (또는 없음 명시)
  - 공지 확인 결과
  - 오늘 첫 지시

7. 적용 범위
- 신솔라·구솔라 둘 다 같은 시작 규칙을 쓴다. 터미널 세션, 메신저 세션
  구분 없이 동일하다.
- 구솔라는 현재 Sleep 상태라 당장 아침/저녁 의식을 실행할 일은 없지만,
  나중에 깨울 때를 대비해 시작 설정 경로는 미리 맞춰둔다.

8. GitOps 작업 큐 (2026-09-14 신설)
- 탐(및 페이브 등 심플리파이어 크루)이 신솔라에게 작업을 맡길 때는
  이 저장소의 `tasks/pending/`에 작업 파일을 쓰고 push한다.
- 신솔라는 주기적으로 `git pull`해 새 작업을 확인하고,
  `hermes chat --oneshot --query "..."`로 1회 실행한다.
- 완료되면 `tasks/done/`으로 옮기고 push한다.
- 공유 파일·절 이름에 `HERMES.md` 문자열을 쓰지 않는다(solar-bible.md
  §10 참고, Anthropic 과금 버그 실측 확인됨).
- 상태값은 QUEUED → RUNNING → (WAITING_APPROVAL | BLOCKED) → VERIFYING
  → (DONE | FAILED | CANCELLED)로 기록한다.

이 문서는 솔라바이블 본문을 실제 운영에 붙일 때의 세팅 기준이다.

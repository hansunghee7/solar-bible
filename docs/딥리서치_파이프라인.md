# 딥리서치 파이프라인 (실측 반영판, 2026-09-19)

Claude 토큰을 아끼기 위해 웹 수집과 대량 파일 처리는 헤르메스가 하고, 클로드 에이전트는 결과를 읽고 판정만 한다.
이 문서는 사장님이 준 기술 사양서를 **실제 구현 상태와 대조해서** 정리한 것이다. 없는 기능을 있다고 쓰지 않는다.

## 1. 구조 (5단계)
1. 클로드 에이전트가 발주한다(동기 또는 비동기).
2. 헤르메스가 웹 조사와 자료 수집을 한다. 주장마다 출처 URL과 원문 인용(15단어 이내)을 붙인다.
3. 제미나이가 검증한다. 자체 리서치는 시키지 않고, 헤르메스가 가져온 출처와 주장을 대조만 한다(`docs/AI_POOL_제미나이_검증_프로세스.md`).
4. 결과를 `tasks/done/` 또는 지정한 보고서 경로에 저장한다.
5. 의뢰한 클로드 에이전트가 결과를 읽고 증거를 확인한 뒤 최종 판정한다.

## 2. 구현 상태 (탐 실측)
| 항목 | 상태 | 근거 |
|---|---|---|
| 동기 발주(`hermes chat --oneshot --query "..."`) | **동작** | 왕복 약 12초 실측. 긴 조사는 백그라운드로 실행하고 결과를 파일로 받는다 |
| 비동기 발주(`tasks/pending/` 파일, 3분 폴러) | **동작** | 오늘 지시서 다수 처리 확인 |
| 결과 표준 서식(TASK/EXECUTION/OBSERVATION/VERIFICATION/STATUS) | **동작(권장)** | 지시서 공통 규칙에 포함, 완료 파일 대부분 준수 |
| 새 결과 알림: 클로드 세션 시작 훅 | **동작** | `hermes_results.py`가 새 `tasks/done` 결과를 요약 출력. 이미 열린 세션에는 즉시 반영되지 않음 |
| 긴급 알림: 우편함 `--urgent` → 텔레그램 | **동작** | 사장님 폰 도착 확인(2026-09-19) |
| `hx` 래퍼(명령 한 줄 동기 발주) | **미구현** | 실행 파일 없음. 백로그 |
| 업로드 이벤트 훅(`hermes_results.py --event ... --target ...`) | **미구현** | 스크립트가 인자를 받지 않음. 헤르메스가 업로드 시 호출하는 장치도 없음 |
| `tasks/done` 신규 파일 즉시 감지(파일 감시) | **미구현** | 감시 장치 없음. `FileChanged` 훅 시험이 백로그 |
| 제미나이 검증 자동 실행 도구 | **미확인** | 저장소·헤르메스 스크립트·스킬에서 검증 실행 도구를 찾지 못함. 도구가 없으면 보고서에 "검증 단계 미실행"이라고 적는다 |

## 3. 지금 쓰는 방법
- **짧은 조사(약 1분 이내)**: `hermes chat --oneshot --query "<지시문>"`. 지시문에 절대 경로와 산출물 경로를 적는다.
- **긴 조사(15턴 이상)**: 위 명령을 백그라운드로 돌려 출력을 파일에 저장하거나, `tasks/pending/`에 지시서를 넣는다.
- **결과 받기**: 지정한 경로의 파일을 직접 읽는다. 클로드 세션은 시작 때 훅이 새 결과를 알려 준다. 급하면 우편함에 `--urgent --ask "..."`로 사장님께 알린다.

## 4. 지켜야 할 규칙
1. 헤르메스에게는 **절대 경로만** 준다. 넓은 범위 재귀 스캔 금지.
2. 검증은 결과 파일의 **원문 출력**(해시, 로그, 표)으로만 한다. "완료했다"는 말은 증거가 아니다.
3. D 드라이브(HDD)의 자료는 삭제·이동하지 않는다. C 드라이브 여유 공간은 15% 이상 유지한다(§10).
4. 공개 저장소이므로 키, 토큰, 호스트명, IP, 개인정보를 결과에 쓰지 않는다.
5. 완료 보고에는 `python C:\Users\PC\AppData\Local\hermes\scripts\evidence_snapshot.py <저장소 경로>` 출력을 붙인다.

## 5. 미구현 항목의 우선순위 (백로그)
1. `hx` 래퍼: 동기 발주를 명령 한 줄로 하고 결과를 자동 저장한다.
2. 업로드 완료 알림: 헤르메스가 결과 저장 후 우편함으로 알리는 방식이 가장 단순하다(이미 있는 우편함 재사용).
3. 제미나이 검증 도구: 주장별 출처 대조를 실행하는 스크립트(verdict JSON)를 만들고, 없으면 "미실행"을 보고서에 기록한다.
4. 열린 세션에 즉시 알리는 방법: 딥리서치 보고서(`reports/2026-09-19-realtime-push-research.md`)의 결론에 따라 선택한다.

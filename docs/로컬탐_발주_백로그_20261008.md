# 로컬탐 발주 백로그 (2026-10-08, 탐 클라우드)

역할: 로컬탐은 **지휘**(발주, 감시 걸기, 5줄 요약, 1줄 판정)만 한다. 일은 엔진에 보낸다. 이번 주 한도가 90% 찼으니 본체 호출을 아낀다.

## 지휘 규칙 (크레딧 최소)
- 본체 도구 호출은 세션당 30회 이내. 파일은 `grep`·`head`·줄 범위로만 읽는다. 결과 보고는 5줄.
- 엔진 순서: 스크립트 → 타미(솔라·플래시 무료) → 로컬 LLM → 제미나이 API·Vertex(GCP 크레딧) → 덱스·비티(검증). 소넷 서브에이전트는 쓰지 않는다.
- 폴링 금지. 발주하면 결과는 `notify/` 푸시(깃액션 봇)로 오고, 시각이 아니라 사건을 기다릴 때는 감시를 건다.
- 컨텍스트 40%를 넘으면 중단하고 인수인계를 남긴다. 결과는 `mailbox/탐/`에 올린다(탐 클라우드에 푸시됨).
- 쓰기 거부가 나면 우회하지 말고 보고한다. 비밀값은 출력하지 않는다.

## 백로그 (위에서부터)
- **B1 신PC 클론 복구** · 엔진 스크립트. `git -C C:/work/solar-bible pull --ff-only` 후 `bash C:/work/solar-bible/tasks/assets/repair_poller_clone.sh`. 성공 증거: `notify/repair-poller-clone-done.md` 푸시. 끝나기 전에는 타미 발주를 하지 않는다(클론이 깨져 있어 실패한다).
- **B2 타미 재실행 3건** · 엔진 타미. B1 뒤에 `tasks/done/`의 원본 3건을 새 이름으로 `tasks/pending/`에 복사해 발주: ① 제미나이 검색 보충 리서치(pushalert2, followup, 하루 1회 규칙 주의) ② 덱스 3차 자문 ③ 제미나이 웹 확인의 신PC 부분(출력이 비어 있었음, python 경로 확인). 결과는 스크립트가 직접 게시한다.
- **B3 구PC 폴러 감시 설치** · 엔진 타미(ssh `goosolar`). `tasks/assets/pending_watchdog.sh`를 `DRY=1`로 1회 실행해 출력 확인, 5분 cron 등록, 첫 자동 실행 확인. `scripts/ops/jobs.toml` 등록 PR 1건만 로컬탐이 작게 직접 한다.
- **B4 텔레그램 답장 접수 준비** · 엔진 타미(읽기 전용). `tg_boss.py`가 쓰는 봇과 헤르메스 게이트웨이가 같은 봇을 읽는지 확인(토큰·id 값 출력 금지), 결과만 보고. 겹치면 새 봇이 필요하고 봇 생성은 사장님 몫이다. 겹치지 않으면 `tasks/assets/telegram_inbox.py` 설치를 타미에게 발주.
- **B5 숙제 초안 3종** · 엔진 제미나이 API(Vertex 크레딧)로 초안, 덱스·비티로 검증. 재료는 비공개 simplifier-cxo-db 이슈 #425(대표님 회신 요약). ① 월요일 환경 확인 체크리스트(브랜치 보호, 키 분리, 읽기 전용 토큰, 보안 조언) ② AI에 넣어도 되는 데이터 규칙 1장 ③ 에이전트·지침·저장소 한 장 목록 v0(Notion 허락 전이라 모르는 칸은 "확인 필요"). 로컬탐은 각 초안의 5줄 요약과 1줄 판정만 올리고 최종 정리는 탐 클라우드가 한다.
- **B6 (선택, 사장님 시간 있을 때)** 반복 도중 중지 시험 · 엔진 스크립트(`scripts/ops/chatroom_stopcheck.py` 기반). 사람 `중지`가 필요하다.

## 🟢 탐 (2026-09-14): 솔라바이블 정본 이관 + GitOps 큐 신설

심플리파이어 CLAUDE.md·진행상황.md 체계와 대조해 솔라바이블을 점검하고,
사장님과 함께 아래를 확정·실행했다.

- **정본 경로 이관**: `C:/work/solar-bible.md`(임시)에서 이 저장소
  (`hansunghee7/solar-bible`)로 이관 완료. `solar-bible.md`는 루트,
  `docs/solar-bible-setup.md`도 커밋 완료.
- **GitOps 작업 큐 신설**: `tasks/pending/`·`tasks/done/` 폴더 생성 완료.
  탐(및 페이브 등 심플리파이어 크루)이 `tasks/pending/`에 작업을 쓰면
  신솔라가 폴링해 `hermes chat --oneshot --query`로 실행하고
  `tasks/done/`으로 결과를 옮기는 구조.
- **탐↔신솔라 채널은 텔레그램이 아니라 Git(파일)로 고정**: 신솔라의
  텔레그램 게이트웨이가 터미널 리셋 시 맥락을 잃는 문제가 실측으로
  확인됐다(사장님 보고). 터미널·세션에 안 묶이는 GitOps 쪽이 더 안전.
- **신솔라·구솔라 역할 확정**: 신솔라(신PC) = 지휘, 구솔라(구PC) = 실행
  (+4090 웨이크업 트리거). 구솔라는 현재 관리 부담으로 Sleep 상태 -
  명확한 활용처가 생기면 사장님이 다시 켠다. 그 전까지 탐의 GitOps
  상대는 신솔라 하나뿐이고, 구솔라 위임은 Hermes 내부에서 신솔라가
  판단할 일(탐이 직접 큐를 나누지 않는다). 자세한 근거는
  `solar-bible.md` §13 참고.
- **Control API 검토 결과**: 사장님이 "위임"을 "지휘·통제"로 올리라고
  요청해, Nous Research Hermes Agent 공식 저장소를 원자료로 확인했다.
  REST/gRPC Control API 없음, Hermes를 MCP 서버로 노출하는 기능도 없음
  (MCP는 클라이언트 방향만 지원). 있는 건 CLI 인터랙티브 제어(Ctrl+C,
  /retry, /undo)와 메신저 게이트웨이뿐. 그래서 GitOps 1단계를 유지하고,
  `STATUS.md` 상태머신(QUEUED→RUNNING→WAITING_APPROVAL/BLOCKED→
  VERIFYING→DONE/FAILED/CANCELLED)으로 통제 루프를 최대한 흉내낸다.
- **보안 확정 사항**: 공유 작업 파일·절 이름에 `HERMES.md` 문자열을
  쓰지 않는다. Claude Code가 git 커밋 메시지의 이 문자열을 서드파티
  하네스 탐지용으로 스캔하다 실제로 한 사용자에게 종량제 과금을 몰래
  물린 사고가 있었다(Anthropic 공식 저장소 이슈 #53262, 탐이 원자료로
  직접 확인).

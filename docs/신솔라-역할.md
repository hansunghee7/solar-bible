# 신솔라(이 PC) 역할 문서

신PC에서만 확인한 사실 기준. 구PC(구솔라) 항목은 "구PC 접근 불가로 미확인"로만 표기한다.

## 1. 역할

신솔라(이 PC)는 Solar Bible 체제에서 지휘(Supervisor) 역할을 맡는다. 저장소의
`tasks/pending/`을 주기적으로 `git pull`해서 폴링하는 GitOps 폴러이고, 받은
작업은 `hermes chat --oneshot`으로 1회 실행한다. LLM 호출은 이 PC의 4090 GPU에서
돌아가는 Ollama(`localhost:11434`)가 기본 제공자로 쓰인다(`config.yaml`의
`model.provider: nous` 기준). Hermes API Server(127.0.0.1:8642)와 MCP Adapter도
이 PC에서 실행 중이며, 로컬 Claude Code 세션은 SSH(22번) 또는 동일 PC 직접 호출로
헤르메스에 접근한다. 짧은 조사성 과제는 직접 호출(동기), 긴 작업·배치는 GitOps 흐름이 기본이다
(`docs/hermes-channel-design.md` 참조).

## 2. 설치 위치

- Hermes Home: `C:\Users\PC\AppData\Local\hermes`
- 이 git 클론 경로: `C:/work/solar-bible` (원격 `origin/main`에서 pull 중)

## 3. 서비스 (이 PC 실행 중)

- **Hermes** — `/c/Users/PC/AppData/Local/hermes/bin/hermes` 실행 중
  - Hermes API Server: `127.0.0.1:8642`
  - MCP Adapter: `127.0.0.1:8765/mcp` (Streamable HTTP, 도구 4개)
- **OpenSSH Server (sshd)** — `0.0.0.0:22` 수신 중(Tailscale 망 안에서의 SSH 직결 허용)
- **Ollama** — `0.0.0.0:11434` 수신 중(LLM provider, localhost 기준 `http://localhost:11434`)

IP/MAC은 공개 저장소 비노출 원칙상 적지 않는다. 이 PC가 Tailscale에 연결되어 있고
원격 접속은 Tailscale IP로만 가능하다는 점만 표기한다(구체적 IP는 생략).

## 4. LLM endpoint

- Ollama: `http://localhost:11434`
- 현재 Ollama 버전: 0.34.0 (실측 확인)
- Hermes `config.yaml`의 `model.provider` 설정에 따라 요청이 Ollama로 라우팅된다
  (기본 스냅샷 기준 `provider: nous`).

## 5. 접근 방법

자세한 채널 분기와 호출 명령은 `docs/hermes-channel-design.md`에 정리돼 있다.
요약:

- **로컬에서 직접 호출**: 동일 PC에서는 `hermes chat -q "..."` (또는 stdin 방식).
- **SSH 직결**: 다른 기기에서 Tailscale 망을 통해 `ssh <user>@<PC-Tailscale-IP> hermes chat ...`.
  bash 클라이언트와 PowerShell 클라이언트 각각의 따옴표/표준입력 규칙이 다르므로
  문서에 나온 형태 그대로 쓴다.
- **GitOps(파일)**: `tasks/pending/` 폴링 → 실행 → `tasks/done/` push.
  클라우드 세션처럼 SSH egress가 막힌 환경에서는 이 경로만 쓴다.

## 구PC(구솔라) 쪽

구솔라(구PC)의 현재 상태·설치 위치·서비스·접근 방법은 구PC가 파킹(Sleep) 상태라
이 세션에서 확인할 수 없다. 구PC 역할·시작 절차는 `docs/역할노트-구솔라.md`를 참고하되,
실제 값은 구PC를 깨워서 확인해야 한다. 추측해서 적지 않는다.
